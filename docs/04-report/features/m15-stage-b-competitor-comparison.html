M-15 Stage B 경쟁 터미널 비교 실행 보고

Stage B는 GhostWin 내부 성능 숫자가 아니라 Windows Terminal, WezTerm, Alacritty와의 외부 비교를 닫기 위한 작업이다. 이번 실행에서는 세 경쟁 터미널 설치와 버전을 확인했고, 기존 비교 보조 스크립트를 현재 WPF 앱 구조에 맞췄으며, 엄격한 외부 p95 측정은 PresentMon 권한 조건 때문에 보류 판정했다.

설치 확인 완료 WT / WezTerm / Alacritty / GhostWin Release 실행 파일을 확인했다.
비교 보조 스크립트 보정 GhostWin.App 프로세스명과 JSON/CSV 선명도 산출을 반영했다.
외부 p95 보류 PresentMon은 확보됐지만 현재 비관리자 세션에서 CSV가 생성되지 않았다.

지금 어떻게 측정해야 하나

1. 대상 실행
4개 터미널을 같은 쉘/폰트/창 크기로 실행
2. 동일 입력
같은 문자열 또는 workload를 각 터미널에 입력
3. 외부 계측
PresentMon을 프로세스 ID 기준으로 붙여 CSV 수집
4. 비교 판정
3회 중 2회 이상 같은 방향이면 열세/동급/우위 판정

GhostWin 자체 p95는 GHOSTWIN_RENDER_PERF 내부 로그로 이미 Stage A에서 측정할 수 있다. 하지만 경쟁 터미널에는 같은 내부 로그가 없으므로, Stage B의 공정 비교는 PresentMon 같은 외부 프레임 계측으로 맞춰야 한다.

수정한 비교 보조 스크립트

파일 이전 문제 개선
scripts/arrange_compare.ps1 GhostWin을 옛 WinUI 프로세스명 ghostwin_winui로만 찾음. 대상이 없으면 인덱싱 오류 가능. GhostWin.App 우선 탐색, 프로세스 부재 시 안전하게 건너뜀.
scripts/input_all_terminals.py 클립보드 입력이 문자열 quoting에 취약했고 GhostWin WPF 프로세스를 찾지 못함. stdin 기반 Set-Clipboard로 quoting 문제를 줄이고 GhostWin.App을 탐색.
scripts/compare_sharpness.py 콘솔 출력과 루트 스크린샷만 남아 보고서 재사용이 어려움. --output-dir를 받아 sharpness_summary.json / .csv를 남김. 화면 캡처 권한이 없으면 sharpness_error.json으로 원인을 남김.

왜 p95 숫자를 만들지 않았나

숫자를 억지로 만들면 GhostWin 내부 로그와 경쟁 터미널 외부 캡처가 섞여 비교 기준이 달라진다. 또 PresentMon probe는 현재 비관리자 세션에서 CSV를 만들지 못했다. 이 상태에서 빈 CSV나 한쪽만 다른 지표를 표에 넣으면, “경쟁사 대비 빠르다/느리다”는 결론이 재현 불가능해진다.

화면 선명도 스크립트도 현재 Codex 실행 컨텍스트에서는 ImageGrab.grab()이 screen grab failed로 실패했다. 스크립트는 이제 이 상황을 예외 trace 대신 sharpness_error.json으로 남긴다.

보류 판정: Stage B의 엄격한 “시나리오 × 4 터미널 p95 교차표”는 관리자 권한으로 PresentMon을 실행하거나, 별도 ETW 수집 권한을 확보한 세션에서 다시 수행해야 한다.

다음 실행 절차

단계 명령 / 행동 완료 기준
1 관리자 PowerShell에서 PresentMon Console portable exe를 실행 가능한 위치에 둔다. presentmon --help와 3초 캡처 CSV 생성 확인
2 4개 터미널을 같은 창 크기와 같은 workload로 띄운다. 대상 프로세스 ID가 각각 분리되어 기록됨
3 idle / resize / load를 각 3회 반복한다. 각 run의 PresentMon CSV와 summary 생성
4 3회 중 2회 이상 같은 방향이면 열세/동급/우위를 판정한다. M-15 문서의 G2 외부 비교 gap closure

결론

이번 Stage B 세션은 “경쟁 터미널 비교를 실행 가능한 상태로 정비하고, 현재 권한 조건에서 엄격 p95가 왜 보류되는지 증거로 남긴 작업”이다. 설치/버전 확인과 보조 스크립트 보정은 완료됐지만, 최종 성능 우열 판정은 elevated PresentMon CSV가 생긴 뒤에만 확정한다.
